# Public repository control matrix

**Snapshot:** 2026-07-25

This matrix is a current public-presentation and control review of the 12 scoped Conxian repositories. At the snapshot, every scoped repository was observed as **public**, **unarchived**, and defaulting to **`main`**; each row still records `Public / main` explicitly. This is not a security certification, production-readiness attestation, or full repository-history and secret audit. Sampled current surfaces showed no concrete exposed credential values, while [#47](https://github.com/Conxian/.github/issues/47) owns deeper public/private-boundary and preventive-control verification.

The category column applies the terms defined by the normative [repository taxonomy](../repository-taxonomy.md) without redefining them. Release requirements, exemptions, version authority, and evidence rules are normative in the [public release discipline](./release-discipline.md); this matrix records only the snapshot posture and resulting decisions. Portfolio positions retain the groupings in the [documentation hub](./index.md); `.github`, `conxian.github.io`, and `conxian-labs-site` are described by their distinct public functions rather than forced into those two groups.

## Decision terms

**Presentation posture** is limited to the repository's current public framing:

- **Acceptable:** purpose, audience, and operating expectation are sufficiently clear for the current role.
- **Acceptable with clarification:** the repository can remain public as presented, but named README or metadata inconsistencies should be corrected.
- **Review before promotion:** keep the surface available, but resolve the named ambiguity before increasing its portfolio prominence or treating it as an authoritative entry point.

**Release action** is the concrete follow-up priority under the public release discipline, not a security score:

- **None:** no release tightening is expected for the repository class.
- **Low:** small documentation or metadata alignment with no material release ambiguity.
- **Medium:** policy, deployment, or version signaling needs a bounded reconciliation.
- **High:** current release, source, artifact, or readiness signals materially diverge and should be reconciled before promotion.

## Release class and exemption decisions

The normative details remain in the [public release discipline](./release-discipline.md). The matrix records these explicit decisions:

- **Libraries / SDKs:** `lib-conxian-core` and `conxius-enclave-sdk` require tagged GitHub Releases for externally consumable versions.
- **Protocol / runtime / integration:** `Conxian`, `conxian-gateway`, `conxian-nexus`, and `conxius-platform` require tagged releases for public compatibility or milestone changes; clearly labeled development between milestones may remain unreleased.
- **End-user applications / tools:** `conxius-wallet`, `conxian_ui`, and `conxius-orbit` require a release signal when a user-facing or distributed version changes.
- **Governance / static support:** `.github`, `conxian.github.io`, and `conxian-labs-site` are exempt from routine releases but require purpose, canonical-destination, and applicable deployment-traceability signals. Site releases are optional for meaningful milestones.

A raw Git tag does not satisfy a required published GitHub Release. Repository-local issues own remediation; `.github` owns the shared policy and exception roll-up.

## Explicit outliers and ambiguities

- **Release/source divergence:** `lib-conxian-core`, [`conxius-wallet`](https://github.com/Conxian/conxius-wallet/issues/356), `conxius-enclave-sdk`, and `conxius-orbit` publish release versions behind source or documentation signals.
- **Release evidence or cadence gaps:** `Conxian` has a final tag newer than its latest release; `conxian-gateway` lacked its runbook's release assets; `conxius-platform` and the gateway had substantial snapshot-only commit gaps after their latest releases; `conxian_ui` lacks a clearly visible tag-driven path. Commit-ahead counts and release values are observations from 2026-07-25, not durable repository properties.
- **Static/deployment clarity:** `conxian.github.io` lacks basic purpose, destination, and release/deployment guidance; `conxian-labs-site` needs its deployment-versus-release wording reconciled.
- **Canonical front-door ambiguity:** `conxian.github.io` is designated as the docs landing page but lacks local ownership and repository metadata, and its custom domain did not resolve during the snapshot.
- **Role/promotion ambiguity:** `conxian_ui` alternates between definitive interaction surface and supporting/reference wording; `conxius-platform` needs an explicit operator-only posture; `conxius-orbit` should not be promoted until its version and legacy references are normalized.
- **License metadata mismatch:** `Conxian`, `lib-conxian-core`, and `conxian-nexus` need repository metadata to reflect the license files and intended licensing model accurately.
- **Ownership ambiguity:** `Conxian` has both GitHub-precedence and root ownership files; `conxian.github.io` has only organization-default ownership.

## Method and limitations

- Reviewed current repository metadata, default branches, archive state, topics, ownership files, root README and release surfaces through GitHub on 2026-07-25.
- Compared the public role labels with the normative taxonomy, documentation-hub grouping, and organization-profile pin recommendation.
- Sampled high-signal README, workflow, manifest, changelog, governance, license, domain, and release-policy files; this was not an exhaustive code, commit-history, binary-artifact, dependency, deployment, or credential audit.
- DNS/domain observations and commit-ahead counts are point-in-time checks. Release pages identify published GitHub Releases, not every tag, package registry artifact, deployment, or downstream build.
- “Public-safe” here means no concrete exposed credential value was identified in the sampled current presentation and no listed surface alone required immediate removal. It does not mean the repositories are secure, production-ready, or free of sensitive material; [#47](https://github.com/Conxian/.github/issues/47) owns that verification boundary.
